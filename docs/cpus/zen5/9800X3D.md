# Ryzen 7 9800X3D support

This profile uses PM-table version `0x620105`: 1828 bytes, 457 little-endian
`float32` values, and eight physical cores. Shared sensor, limit, rail, and
control behaviour is described in the [Zen 5 X3D overview](README.md).

## Per-core telemetry

| Display or export field | Float indices | Count | Unit |
|---|---:|---:|---|
| Core voltage | `d[309..316]` | 8 | V |
| Core temperature | `d[317..324]` | 8 | °C |
| Core frequency | `d[325..332]` | 8 | GHz |
| Core power | `d[333..340]` | 8 | W |
| Core C0 residency | `d[341..348]` | 8 | % |
| Core CC1 residency | `d[349..356]` | 8 | % |
| Core CC6 residency | `d[357..364]` | 8 | % |
| Per-core boost limit | `d[373..380]` | 8 | GHz |

Core frequency is displayed in MHz. `d[341..348]` is the direct C0 residency:
each lane is the complement of its corresponding CC1 lane in the captured
dump. `d[357..364]` is the separate CC6 residency lane.

The **Core residency** dashboard group contains direct C0, CC1, and CC6
residency values. The raw JSON snapshots preserve all PM-table values by
float index; the named CSV export includes per-core boost limits.

## Temperature telemetry

| Display field | Source | Unit |
|---|---:|---|
| Per-core temperatures | `d[317..324]` | °C |
| CCD0 L3 Cache | `d[448]` | °C |
| CPU CCD0 | SMN `0x59B08` | °C |
| CPU Hotspot (exporter) | `d[270]` | °C |
| Slow temperature field 0 (exporter) | `d[298]` | °C |
| Slow temperature field 1 (exporter) | `d[299]` | °C |

Tctl/Tdie, IOD lanes, and thermal status are shared direct-SMN sensors and
are listed in the [Zen 5 X3D overview](README.md).

## Curve Optimizer

Per-core Curve Optimizer uses MP1 messages `0x50..0x57`, one message per core,
with a signed 32-bit margin argument.
